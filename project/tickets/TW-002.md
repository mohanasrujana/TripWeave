# TW-002 — Bootstrap Spring Boot API

- Status: Complete
- Completed: September 1, 2026
- Commit: `63e70bb` (`Completed Spring Boot API bootstrap`)

## Goal

Create a small but production-shaped Java API with one documented endpoint and
a repeatable local quality command.

## What I built

- Created a Java 21 Spring Boot 4.1.1 Maven project in `services/api`.
- Used package `com.tripweave.api` and added Web, Validation, and Actuator
  dependencies.
- Added `GET /api/health` in `HealthController`.
- Returned the JSON response `{"status":"UP"}` from the health endpoint.
- Added a direct unit test for the controller without starting Spring.
- Added an MVC slice test for the HTTP status, content type, and JSON response.
- Kept the generated application-context test to verify that Spring starts.
- Added the Maven Wrapper so the project does not depend on a developer's
  globally installed Maven version.
- Added Spotless with Google Java Format and a wildcard-import check.
- Added Checkstyle and a project rules file.
- Documented setup, startup, endpoint verification, tests, and quality checks in
  `services/api/README.md`.

## Endpoint

```http
GET /api/health
```

Expected response:

```json
{"status":"UP"}
```

## Verification I ran

From `services/api`:

```bash
./mvnw verify
```

This single command ran the test suite, Spotless, and Checkstyle. The verified
result was:

- 3 tests passed with no failures, errors, or skipped tests.
- Spotless completed successfully.
- Checkstyle reported 0 violations.
- Maven finished with `BUILD SUCCESS` under Java 21.0.12.1.

I also started the service and manually checked the endpoint:

```bash
./mvnw spring-boot:run
curl http://localhost:8080/api/health
```

## Problems I ran into

- The initial tests covered MVC and application startup, but the ticket also
  required a unit test. I added `HealthControllerUnitTest` so the controller's
  behavior is checked without Spring.
- After changing `pom.xml`, VS Code showed stale Maven project metadata. I set
  `java.configuration.updateBuildConfiguration` to `automatic` in the local
  workspace settings. If it returns, I can run **Java: Clean Java Language
  Server Workspace** and select **Reload and delete**.
- One automated Maven run could not write to the user-level `.m2` cache. Running
  the command in my normal shell used the correct cache permissions.
