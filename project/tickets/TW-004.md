# TW-004 — Add PostgreSQL/PostGIS local environment

- Status: Complete
- Started: September 4, 2026
- Completed: September 5, 2026
- Implementation commit: `776f9a9` (`Add PostgreSQL and PostGIS`)

## Goal

Provide a repeatable local PostgreSQL/PostGIS environment, connect the Spring
Boot API to it, and prove that a versioned migration succeeds from a clean
database volume.

## What I have done

- Added a Docker Compose database service using a digest-pinned PostgreSQL
  17/PostGIS 3.5 image.
- Declared `linux/amd64` explicitly because the official image is amd64-only and
  the local Docker engine is aarch64.
- Added a persistent named volume and a PostgreSQL readiness health check.
- Documented the database name, user, password, host, and port in
  `.env.example`; the real `.env` remains ignored by Git.
- Added Spring JDBC, the PostgreSQL driver, and Spring Boot's Flyway starter to
  the API.
- Configured the API datasource exclusively through environment variables.
- Added Flyway migration `V1__enable_postgis.sql` to make the PostGIS extension
  an explicit database requirement.
- Expanded the local-development runbook with setup, shutdown, migration
  verification, and destructive clean-volume recovery instructions.

## Verification I ran

From the repository root:

```bash
docker compose config --quiet
docker compose up -d database
docker compose ps database
docker compose exec database psql -U tripweave -d tripweave -c "SELECT PostGIS_Version();"
```

Verified:

- The Compose configuration is valid.
- The database container reaches the `healthy` state on port 5432.
- PostgreSQL reports PostGIS 3.5 with GEOS and PROJ enabled.

With the variables from `.env` exported, from `services/api`:

```bash
./mvnw verify
```

Verified:

- The API application context connects to PostgreSQL.
- Flyway applies version `1` on a newly created database volume.
- The API tests, Spotless, and Checkstyle pass.
- The final Flyway history check was user-reported as successful; its complete
  terminal output was not retained in the ticket record.

## Important implementation choices

- The image includes both a version tag and registry digest so an upstream tag
  change cannot silently alter the local database image.
- The official PostGIS image is used through Docker's amd64 emulation rather
  than relying on an unofficial ARM image.
- Credentials are not embedded in Compose or Spring configuration.
- Flyway owns schema changes so future database evolution remains ordered and
  repeatable.
